API Reference

Every route the FastAPI server exposes, as implemented in server.py.

Base URL & interactive docs All examples below assume the server is running locally at http://localhost:8000. FastAPI also auto-generates interactive Swagger/OpenAPI docs at /docs and /redoc on the running server itself — this page is a hand-written companion to those, not a replacement.
Auth required almost everywhere Every route except /auth/google, /auth/google/callback, /auth/logout, and /health requires a valid access_token cookie (set by completing the Google sign-in flow in a browser). Calling these with curl means first signing in via a real browser and copying the cookie, e.g. curl -b "access_token=<jwt>" ....
Session access is a membership question Most routes below are scoped to a session a given user is a member of, not just one they created — see Session membership & roles. Routes marked "Admin only" additionally require role = 'admin' on that membership row.

Auth

Method & PathAuthDescription
GET /auth/google — Redirects the browser to Google's OAuth consent screen.
GET /auth/google/callback — OAuth redirect target. Exchanges code for a token, upserts the user, sets the access_token cookie, redirects to /. On error or a missing code, redirects to /?auth_error=1.
GET /auth/me cookie Returns the current user. 401 if not signed in.
POST /auth/logout — Clears the access_token cookie.

GET /auth/me

curl http://localhost:8000/auth/me -b "access_token=<jwt>"
{
  "id": 1,
  "email": "you@example.com",
  "name": "Your Name",
  "avatar_url": "https://..."
}

Session management

Method & PathAuthDescription
GET /api/sessions member List every session the current user is a member of (not just ones they created), newest-updated first.
POST /api/sessions cookie Create a new session. Optional body overrides the provider/model. Creator is inserted as admin.
PATCH /api/sessions/{session_id}/name member Rename a session. Any member may rename — no admin requirement.
DELETE /api/sessions/{session_id} admin Delete a session (DB row, cascading children, checkpoint thread, in-memory cache, and lock entry).

GET /api/sessions

curl http://localhost:8000/api/sessions -b "access_token=<jwt>"
[
  { "id": "abc-123", "name": "Dinner at Spice Garden", "created_at": "...", "updated_at": "..." }
]

POST /api/sessions

curl -X POST http://localhost:8000/api/sessions \
  -b "access_token=<jwt>" \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "model": "gpt-4o"}'

Body is optional — {} uses the configured defaults (config/defaults.yaml). Response: 201

{ "session_id": "abc-123", "name": "New Session", "provider": "openai" }

PATCH /api/sessions/{session_id}/name

curl -X PATCH http://localhost:8000/api/sessions/abc-123/name \
  -b "access_token=<jwt>" \
  -H "Content-Type: application/json" \
  -d '{"name": "Vegas trip"}'

DELETE /api/sessions/{session_id}

curl -X DELETE http://localhost:8000/api/sessions/abc-123 -b "access_token=<jwt>"

Note: an equivalent DELETE /sessions/{session_id} (no /api prefix) also exists under the chat routes below and does the same thing.

Session membership

Method & PathAuthDescription
GET /api/sessions/{session_id}/members member List the session's roster: user_id, name, email, avatar_url, role.
POST /api/sessions/{session_id}/members admin Add an existing user by email as a member. 404 if that email has never signed in. Idempotent — re-adding an existing member is 200, not an error.
DELETE /api/sessions/{session_id}/members/{user_id} admin Remove a member. 400 if this would remove the session's last admin.
PATCH /api/sessions/{session_id}/members/{user_id}/role admin Change a member's role (admin / member). 400 if this would demote the session's last admin.

POST /api/sessions/{session_id}/members

curl -X POST http://localhost:8000/api/sessions/abc-123/members \
  -b "access_token=<jwt>" \
  -H "Content-Type: application/json" \
  -d '{"email": "friend@example.com"}'
{ "ok": true, "already_member": false }

PATCH /api/sessions/{session_id}/members/{user_id}/role

curl -X PATCH http://localhost:8000/api/sessions/abc-123/members/7/role \
  -b "access_token=<jwt>" \
  -H "Content-Type: application/json" \
  -d '{"role": "admin"}'
{ "role": "admin" }

Expense proposal review

New or changed expenses are staged as proposals, not applied immediately — see Expense proposal approval workflow. All three routes below are admin-only.

Method & PathDescription
GET /api/sessions/{session_id}/proposals List pending proposals for the session.
POST /api/sessions/{session_id}/proposals/{proposal_id}/approve Approve a proposal — materializes it into bills/bill_items.
POST /api/sessions/{session_id}/proposals/{proposal_id}/reject Reject a proposal — no effect on bills/bill_items.

GET /api/sessions/{session_id}/proposals

curl http://localhost:8000/api/sessions/abc-123/proposals -b "access_token=<jwt>"
[
  {
    "id": 5,
    "session_id": "abc-123",
    "proposed_by": 3,
    "status": "pending",
    "supersedes_bill_id": null,
    "is_correction": false,
    "payload": {
      "bill_id": "bill_a1b2c3d4",
      "description": "Dinner at Spice Garden",
      "raw_text": "...",
      "tax": 1.9, "tip": 3.0, "paid_by": "Alice",
      "items": [ { "name": "Burger", "price": 12.0, "qty": 1, "assigned_to": [], "shared": false, "unassigned": false, "qty_allocations": {} } ]
    },
    "decided_by": null, "decided_at": null,
    "created_at": "...", "updated_at": "..."
  }
]

is_correction is computed fresh on every read (whether payload.bill_id currently matches an approved bill in this session) — supersedes_bill_id itself is not a reliable signal by the time a proposal is actually reviewed, see the architecture doc for why.

POST .../proposals/{proposal_id}/approve

curl -X POST http://localhost:8000/api/sessions/abc-123/proposals/5/approve -b "access_token=<jwt>"

Returns the decided proposal row (status now "approved"). 409 if it was already decided by someone else first.

Chat & images

Method & PathAuthDescription
POST /sessions/{session_id}/chat member Send a chat message; runs the agent's tool-calling loop (speaker-attributed) and returns its reply plus the updated state.
POST /sessions/{session_id}/image member Upload a receipt image (multipart). Vision model extracts it, then feeds the result into the same chat loop.
GET /sessions/{session_id}/state member Get the current serialized session state without sending a message.
GET /sessions/{session_id}/messages member Full chat transcript for replay when a session is reopened, oldest first. Each row includes a raw user_id (null for agent replies) — resolve sender name/avatar via the members endpoint above.
DELETE /sessions/{session_id} admin Delete the session (same behavior as the /api/sessions delete route above).

POST /sessions/{session_id}/chat

curl -X POST http://localhost:8000/sessions/abc-123/chat \
  -b "access_token=<jwt>" \
  -H "Content-Type: application/json" \
  -d '{"message": "Burger $12, Fries $4, Coke $3. Tax $1.90"}'
{
  "response": "Got it — I've proposed that bill, awaiting admin approval. Who's splitting this one?",
  "state": {
    "participants": [],
    "pending_proposals_count": 1,
    "bills": [],
    "finalized": false,
    "all_bills_ready": false,
    "settlement": []
  }
}

Note bills: [] here — the parsed bill is staged as a proposal, not yet in state.bills. It only appears once an admin approves it via the proposals endpoints above. The server resolves the caller's display name for chat attribution via _speaker_name() (re-fetches the users row — get_current_user itself only ever returns {"id": ...}), and persists the message with user_id set.

POST /sessions/{session_id}/image

curl -X POST http://localhost:8000/sessions/abc-123/image \
  -b "access_token=<jwt>" \
  -F "file=@receipt.jpg"

Response shape is identical to the chat endpoint ({response, state}). Returns 400 if the uploaded file's content type doesn't start with image/.

GET /sessions/{session_id}/state

curl http://localhost:8000/sessions/abc-123/state -b "access_token=<jwt>"

Once calculate_split has run, finalized becomes true and settlement is populated: 

"settlement": [
  { "from": "Bob", "to": "Alice", "amount": 14.3 }
]

Error shape

Standard FastAPI/Starlette error body on any non-2xx response:

{ "detail": "Session 'abc-123' not found" }
StatusWhen
401Missing/invalid/expired access_token cookie.
403Caller is a member of the session but not an admin, on an admin-only route.
404Session doesn't exist, or exists but the caller isn't a member (both return the same 404 — session existence isn't leaked to non-members). Also used for a proposal id that doesn't exist, or exists in a different session.
409A proposal was already approved/rejected by someone else between your read and your decide call.
400Uploaded file to /sessions/{id}/image isn't an image; or a membership change would leave a session with zero admins.
